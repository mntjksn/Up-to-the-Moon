# Up-to-the-Moon — 하늘로 올라라!!

Unity 2D 기반 방치형 모바일 게임입니다.  
캐릭터가 자동으로 하늘을 상승하며 자원을 수집하고, 수집한 자원으로 성장해 더 높은 목표 지점에 도달하는 구조입니다.  
이전 프로젝트(모아이 키우기)에서 다루지 못한 실기기 플랫폼 이슈와 시스템 구조 분리에 집중했습니다.

## 구현 시스템

- **자동 비행** — 캐릭터가 자동으로 상승하며 목표 거리까지 진행
- **자원 수집 / 판매** — 거리 진행도에 따라 해금되는 자원 수집 → 골드 전환
- **업그레이드** — 이동 속도, 수집 효율, 저장 용량 업그레이드
- **블랙홀** — 주변 자원을 자동 흡수, 업그레이드 가능
- **부스트** — 일시적 이동 속도 강화
- **도감 / 배경 해금** — 진행 거리에 따라 배경과 수집 정보 단계별 해금
- **오프라인 보상** — 앱 종료 중에도 자원 수집 누적 후 재접속 시 지급
- **서프라이즈 박스** — 랜덤 보상 드롭 이벤트

## 기술적 고민

### 1. Android 실기기 화면 멈춤 문제 해결 (logcat 디버깅)

에디터에서는 정상 동작했지만, 실기기 테스트 중 화면이 멈추거나 재초기화되는 현상이 간헐적으로 발생했습니다.

- 처음에는 게임 로직 문제로 접근했으나 원인을 찾지 못함
- **adb logcat**으로 기기 로그를 분석한 결과 `surfaceDestroyed → surfaceCreated` 이벤트가 반복 발생 → Android Activity 재생성이 원인임을 확인
- `AndroidManifest.xml`에 `configChanges` 옵션을 추가해 화면 회전 및 크기 변경에 의한 Activity 재생성 차단
- 현상이 완화됐고, 플랫폼 이슈는 로그 기반으로 추적해야 한다는 것을 체득

### 2. Manager 책임 분리를 통한 구조 개선

이전 프로젝트에서 하나의 Manager가 너무 많은 역할을 담당했던 구조를 반성하고, 이번에는 시스템별로 책임을 분리했습니다.

- `SaveManager` / `CharacterManager` / `BackgroundManager` / `UpgradeCostManager` 등 역할 단위로 분리
- 각 Manager가 자신의 데이터만 저장·로드하도록 구성해 기능 수정 시 영향 범위를 한정

## 회고

**어려웠던 점**
- 실기기에서만 재현되는 문제는 에디터로 디버깅이 불가능해 원인을 찾는 과정이 답답했습니다. logcat을 도입하고 나서야 문제를 특정할 수 있었고, 이후부터는 실기기 빌드를 더 자주 하게 됐습니다.

**배운 점**
- 모바일 개발에서 에디터 테스트는 충분하지 않고, 실기기 테스트와 로그 분석이 필수라는 것을 경험했습니다.
- AndroidManifest와 Activity 생명주기가 Unity 게임 실행에 직접 영향을 준다는 점을 배웠습니다.
- Manager를 역할 단위로 나누자 기능 추가나 수정이 이전보다 수월해졌습니다.
